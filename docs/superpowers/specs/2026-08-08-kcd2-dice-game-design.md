# 天国拯救2 风格骰子游戏 Demo — 设计规格

- 日期：2026-08-08
- 状态：已确认
- 技术栈：纯 Web 单页面（原生 ES Module + Canvas 2D），零构建链，静态目录可直接打包为 App（Capacitor/Tauri）

## 1. 概述

实现一个基于《天国：拯救2》（Kingdom Come: Deliverance II）骰子游戏（Farkle 变体）的浏览器 Demo。规则与特殊骰子严格沿用 KCD2 官方设定，视觉风格为「写实拟真」（深色木桌、骨制骰子、暖色烛光）。

包含：玩法设计、核心代码结构、基础素材方案、新手教程、可运行 Demo。

## 2. 玩法设计

### 2.1 计分规则（KCD2 官方规则，完整版）

| 组合 | 得分 |
|---|---|
| 每个 1 | 100 |
| 每个 5 | 50 |
| 恶魔之头 | 通配符：可补任意组合（见 2.3） |
| 三个 1 | 1000 |
| 三个 2 | 200 |
| 三个 3 | 300 |
| 三个 4 | 400 |
| 三个 5 | 500 |
| 三个 6 | 600 |
| 四个同点 | 三同点 ×2 |
| 五个同点 | 三同点 ×4 |
| 六个同点 | 三同点 ×8 |
| 顺子 1-2-3-4-5 | 500 |
| 顺子 2-3-4-5-6 | 750 |
| 全顺 1-2-3-4-5-6 | 1500 |

说明：

- 4/5/6 同点是「每增加一颗，在三同点基础上翻倍」，即四个 1=2000、五个 1=4000、六个 1=8000。
- KCD2 计分表不含「三对」组合（官方无此规则），不实现。
- 组合解析优先级：全顺 1500 > 顺子 1-5 / 2-6 > 同点数 ≥3 颗 > 单 1 / 单 5。可保留组合须能被引擎自动识别并给出提示。

### 2.2 回合流程

1. 开局由玩家（Henry）先手。每回合掷当前所有可用骰子（初始 6 颗）。
2. 掷后必须至少保留一组得分骰，其得分计入本回合暂得分。
3. 保留后二选一：
   - **收手（Pass）**：本回合暂得分写入总得分，轮到对手。
   - **继续（Roll）**：重掷剩余未保留的骰子，继续累计。
4. **热骰**：若全部 6 颗都已被保留，可重掷全部 6 颗继续本回合累计。
5. **爆骰（Bust）**：某次掷骰没有任何得分骰 → 本回合全部暂得分清零，回合立即结束。
6. **投降（Give up）**：任意时刻可弃局认输，对手获胜。

### 2.3 特殊骰子

从 KCD2 官方 42 种骰子中精选 8 种代表性骰子 + 普通骰。每种骰子有独立的 6 面加权概率表（依据官方数据），部分骰子含特殊面：

| 骰子 | 特点（加权概率按官方数据实现） |
|---|---|
| 普通骰 | 6 面均匀（16.7%） |
| 幸运骰（Lucky die） | 偏向 1 和 6 |
| 恶魔之头骰（Devil's head die） | 某面为恶魔之头（通配），各面均匀 |
| 圣人安提俄克骰（Saint Antiochus' die） | 偏向 3 |
| 圣三一骰（Holy Trinity die） | 偏向 3 与 2 |
| 偶数骰（Even die） | 偏向 2/4/6 |
| 奇数骰（Odd die） | 偏向 1/3/5 |
| 厄运骰（Die of misfortune） | 偏向 2/3/4/5，很少出 1/6 |
| 贝恩骰（Unbalanced die） | 偏向 2 |

- 开局前，双方可从「已拥有骰子」中选 6 颗装备。Demo 中双方默认拥有全部精选骰子，AI 使用固定套装（如 6 颗普通骰）。
- 加权面以「面权重表」数据结构表示（每面一个出现权重），掷骰按权重随机。
- 恶魔之头面在计分时作为通配符处理：可代表任意点数参与组合（补三同、补顺子、补 1 或 5 计分），一颗骰子仅参与一个组合；单独掷出恶魔之头本身不计分。

### 2.4 徽章（KCD2 特色机制，Demo 精选 4 个）

| 徽章 | 效果 | 使用次数 |
|---|---|---|
| 转生徽章（Resurrection） | 爆骰后可重掷一次 | 每局 1 次 |
| 木匠优势（Carpenter's Advantage） | 新增组合「切口」= 3+5，值 150 | 常驻 |
| 沃罗得徽章（Warlord） | 本回合得分 ×1.5 | 每局 1 次 |
| 法师徽章（Might） | 掷骰时额外多掷一颗骰 | 每局 1 次 |

- 开局前可选装备，双方各至多装备 1 个徽章（Demo 简化，不做锡/银/金三档）。
- 徽章效果在引擎中作为可叠加 modifier 实现，为后续完整徽章表留扩展点。

### 2.5 目标分（可自定义）

- 开局设置面板可设置目标分：预设 1000 / 1500 / 2000 / 2500，或自定义输入（100–10000 整数）。
- 默认 2000。
- 任一方总得分达到或超过目标分即获胜（KCD2 规则：先达标者胜，无追加回合）。

### 2.6 模式

- **玩家 vs AI**：玩家先手，AI 可选难度（保守 / 激进）。
- **本地双人**：同屏轮流操作，屏幕提示当前玩家。
- 引擎以可序列化状态机实现，为后续局域网联机预留（Demo 不实现联机）。

## 3. 核心代码结构

```
d:\骰子\
  index.html              单页入口（含开局设置面板、主界面、规则手册弹层）
  css\style.css           写实拟真主题样式
  js\
    rules.js              计分纯函数：findScoringCombos / scoreCombination / isBust
    dice.js               骰子定义与掷骰：DICE_TYPES（权重表）、rollDice(weights)
    engine.js             游戏状态机：createGame / reducer（roll/hold/pass/useBadge/giveUp）
    badges.js             徽章定义与生效逻辑
    ai.js                 对手 AI：基于当前局面评估保留/收手决策（保守/激进）
    tutorial.js           新手教程步骤与触发逻辑
    ui.js                 DOM 渲染 + Canvas 2D 骰子绘制（材质/光影/滚动动画）
    main.js               装配、事件绑定、启动
  test\
    rules.test.js         Node 运行的核心规则测试
  docs\superpowers\specs\ 本规格
```

模块职责：

- `rules.js`：无 DOM 依赖的纯函数，输入骰面数组，输出可得分组合列表与最高分，可独立单测。
- `engine.js`：状态机 reducer，state 为纯 JSON（可 JSON.stringify 序列化 → 联机接口基础）。
- `ui.js`：只读 state 渲染，不写业务逻辑；骰子用 Canvas 2D 程序化绘制。
- `ai.js`：只读 state 做决策，与引擎解耦。

## 4. 基础素材方案

- **零外部图片资源**：木桌纹理、骨制骰子、点坑、烛光、皮垫全部由 Canvas 2D 程序化绘制（渐变 + 噪点 + 阴影 + 高光 + 滚动/翻转动画）。
- **字体**：优先加载开源中世纪风格字体（如 Cinzel / UnifrakturCook，Google Fonts CDN），失败回退系统衬线。
- **音效**：WebAudio 程序化合成掷骰碰撞声（无音频文件）。
- **打包**：静态目录直接用 Capacitor 包装为 Android/iOS App。

## 5. 新手教程

- 首次进入自动 3 步引导：① 掷骰 → ② 点击保留得分骰 → ③ 收手记分 / 继续掷（含爆骰说明）。
- 引导气泡 + 高亮对应交互区域；可跳过。
- 常驻「规则手册」按钮 → 弹层展示完整计分表、特殊骰说明、徽章说明。
- 教程状态存 localStorage，可重置。

## 6. Demo 范围与边界

**范围内**：两种模式、完整计分、8+1 种骰子、4 个徽章、自定义目标分、AI 两档难度、新手教程、规则手册、程序化音效。

**范围外（后续扩展点）**：局域网/平台联机（引擎已留序列化接口）、完整 42 骰 + 33 徽章、装备成长/经济系统、3D 渲染。

## 7. 测试策略

- 核心规则（计分表、组合解析、爆骰判定、热骰、目标分判定）用 Node 脚本测试（test/rules.test.js），覆盖官方计分表全部条目。
- UI 与动画为人工验收。

## 8. 验收标准

1. 浏览器打开 index.html（经静态服务器）即可完整游玩一局。
2. 计分与 KCD2 官方表一致（含恶魔之头通配、4/5/6 同点翻倍）。
3. 特殊骰加权效果可感知（多次掷骰统计偏向正确）。
4. 徽章可装备并正确生效。
5. 自定义目标分生效。
6. 新手教程完整可跳过，规则手册可用。
7. 引擎 state 可完整序列化/反序列化。
